## Env Variables with ConfigMaps

### Creating ConfigMaps from YAML

ConfigMaps store configuration data as key-value pairs that can be consumed by pods:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
 name: my-module-config
data:
 KAFKA_BOOTSTRAP_SERVERS: "kafka-cluster:9092"
 INPUT_TOPIC: "raw-data"
 OUTPUT_TOPIC: "processed-data"
 LOG_LEVEL: "INFO"
 ```

Apply such a ConfigMap using:

```bash
oc apply -f my-module-config.yaml
```

### Using ConfigMaps as Environment Variables

Inject ConfigMap values as environment variables in your deployment:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-module
spec:
  template:
    spec:
      containers:
      - name: my-module-container
        image: your-registry/my-module:latest
        envFrom:
        - configMapRef:
            name: my-module-config
```

### ConfigMap Reloading

#### Volume Mounts (File Updates)

You should make sure to allow the module to reload env variables at runtime. For dynamic configuration updates, mount the ConfigMap as a volume in the app Deployment Yaml :

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-module
spec:
  template:
    spec:
      containers:
      - name: my-module-container
        image: your-registry/my-module:latest
        volumeMounts:
        - name: config-volume
          mountPath: /etc/config
      volumes:
      - name: config-volume
        configMap:
          name: my-module-config
```

When mounted as a volume:

- Files in the volume are automatically updated when the ConfigMap changes (typically within a minute)
- Your application must implement file watching to detect and reload the configuration
